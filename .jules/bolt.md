## 2026-07-26 - [Dynamic On-Demand Sub-document Fetching & Pipeline Streamlining]
**Learning:** Bulk pre-fetching/populating nested lists (such as retrieving entire user profiles with 4MB base64 profile pictures of all clan members inside `/api/clans`) leads to massive serialization delays and megabyte-level network payloads. Transitioning the list view to be extremely lightweight, while enabling React Query to fetch fully populated single resources on demand (under `/api/clans/:id`), resolves the bottleneck completely. Furthermore, redundant `$lookup` and `$unwind` stages inside MongoDB aggregation pipelines (such as querying challenges details during leaderboard solvedCount summing) create massive, unnecessary disk/memory joins that can be completely eliminated with index-only scans.
**Action:** Always verify selection projection and population footprint in bulk list APIs. Prefer on-demand single-resource queries for detailed views, and streamline aggregation pipeline stages to query only the fields strictly used in calculations.
